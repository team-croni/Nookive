# 메뉴바와 설정 UX

## 결정

검색 HUD는 검색 입력과 결과 탐색만 담당한다. 색인 폴더 선택, 인덱싱 상태, 재색인, 앱 종료는 macOS 메뉴바 아이콘의 메뉴와 별도 설정 창에서 관리한다.

Nookive는 macOS 메뉴바 상주형 앱으로 실행된다. 앱 활성화 정책을 `Accessory`로
설정해 Dock과 `Cmd + Tab` 앱 전환기에는 표시하지 않고, 메뉴바 아이콘·전역
단축키·설정 창으로 접근한다. 앱을 종료하려면 메뉴바 메뉴의 `Nookive 종료`를
사용한다.

이유:

- 검색창이 열렸을 때 첫 입력까지의 경로가 짧아진다.
- 설정이 검색 결과 레이아웃과 상태를 오염시키지 않는다.
- 메뉴바 앱으로 실행 중인 상태와 인덱싱 상태를 자연스럽게 표현할 수 있다.
- 폴더 권한을 사용자가 명시적으로 승인하는 흐름을 만들 수 있다.

## 최초 실행 구성 요소 설치 창 (Software Installer Assistant)

앱을 처음 설치하고 실행했을 때 필수 모델(임베딩 모델 `EmbeddingGemma 2` 및 음성 ASR 모델 전체)이 준비되어 있지 않으면 자동으로 전용 소프트웨어 설치 창이 실행된다.

1. **설치 창 UX**: 복잡한 설정 형식이나 카드 나열이 아닌, 전형적인 데스크톱 소프트웨어 설치 마법사 형태로 중앙 집중형 네이티브 레이아웃을 제공한다. 공식 Nookive 로고와 심플한 프로그레스 바가 제공된다.
2. **AI 모델 전체 자동 설치**: 창이 열리면 별도의 조작 없이 백그라운드에서 임베딩 및 음성 모델 번들 전체(~2.88GB)의 다운로드가 순차적으로 시작되며, 실시간 프로그레스 바(진행 퍼센트, 완료 용량/총 용량, 파일명 말줄임)를 표시한다.
3. **다운로드 중단 및 안전한 이어받기(Safe Cancellation & Resume)**: 창을 닫거나 앱을 종료할 경우, 원자적 취소 플래그를 통해 즉시 다운로드 루프를 탈출하고 파일 스트림을 flush한다. 부분 다운로드 상태(`.part`)가 안전하게 보존되어 다음에 앱이나 설치 창을 열었을 때 HTTP `Range` 헤더를 통해 중단된 지점부터 이어서 다운로드한다.
4. **설치 완료 및 앱 시작**: 설치가 100% 완료되면 완료 뱃지와 함께 `[Nookive 시작하기]` 버튼이 활성화되며, 클릭 시 설치 창이 닫히고 검색 창(`⌥ Space`)이 나타나 즉시 앱을 사용할 수 있다.


## 메뉴 구조

```text
Nookive 아이콘
├─ 검색 열기                 Cmd+Shift+Space
├─ 인덱싱 상태: 준비됨
├─ 설정…
└─ Nookive 종료
```

인덱싱이 진행 중일 때 상태 메뉴는 `인덱싱 중 · 42%`와 `일시정지`로 바뀐다. 오류가 있으면 검색을 막지
않고 `오류 2개 · 설정에서 보기`로 안내한다.

## 설정 창

현재 구현은 별도 `settings` WebviewWindow(880×720, 그림자 여백 포함)를 만들고, GitHub·VS Code 설정처럼 왼쪽
분류 목록(`SettingsSidebar`)과 오른쪽 내용으로 나눈다. 오른쪽에는 선택한 분류의 제목과 카드만 보인다. 카드 사이는 선 없이
간격으로 나누고, 카드 안의 옵션 줄과 폴더 목록은 채운 상자(`optionGroup`)에 모아 줄 사이에만 얇은 선을 둔다. 위아래 방향키로 분류를 옮길 수 있고, 설정 창은 닫아도 숨기기만 하므로 다시 열면 마지막 분류가 남는다.
설정이 늘어나면 분류 항목을 더한다. 필수 모델이 없을 때만 모델 설치 카드(`ModelSection compact`)가 분류와 관계없이
맨 위에 나타난다.
사용자에게 보이는 문구는 "색인/index" 대신 "검색 데이터/search data"라고 쓴다.

- **검색 데이터**
  - 검색될 폴더: macOS 폴더 선택기로 추가, 제거. 제목 옆에 폴더 수를 보이고, 목록은 폴더 이름순으로 정렬해 이름과
    상위 경로(홈은 `~`)를 두 줄로 보여준다. 폴더가 많아지면 약 6줄 높이에서 목록 안에서 스크롤한다.
  - 검색 상태: 상태 배지, 발견된 파일·생성할 파일·코드 파일 수, 마지막 갱신 시각, 새로고침과 생성 시작/중지,
    진행률(자동 생성이 도는 중이면 같은 진행률). 코드 파일 수는 코드 검색이 켜져 있고 코드 검색 데이터가 있을 때만
    보이며, 내용 대신 이름으로만 찾는 파일(1MB 초과·압축 파일)이 있으면 ⓘ로 이유를 알려준다. 마지막 갱신 시각은
    문서 폴더 동기화(`last_sync_at_ms`)와 코드 검색 데이터 갱신(`get_code_index_status`) 중 더 최근 것이다.
- **검색 방식**
  - 코드 검색 켜기/끄기(기본 켜짐): 검색 폴더의 코드 파일을 검색창의 코드 검색(Tab 또는 `code:`)에서 이름, 경로,
    내용으로 찾는다. 코드 검색 데이터(`code-index.sqlite`)는 검색 데이터 초기화 때 함께 지운다. 켜져 있으면
    "코드 파일 열기"에서 자동(설치된 첫 에디터), 감지된 에디터, 기본 앱 중 하나를 고른다(`nookive.codeEditor`).
    설정은 localStorage(`nookive.codeSearchEnabled`)에 두고 검색 창은 storage 이벤트로 따라간다
  - 웹 검색 켜기/끄기: 끄면 결과가 없을 때의 웹 폴백과 웹 검색 모드(Tab, `web:`)를 모두 쓰지 않는다. 켜져 있으면
    검색 엔진(Google, Bing, DuckDuckGo, Brave Search, Ecosia, Naver, Baidu)을 고른다(`nookive.webSearchEngine`).
    고르지 않았으면 간체 중국어는 Baidu, 나머지는 Google이다. 메뉴는 Google 다음에 지금 언어의 지역 엔진을 올린다. ⓘ 안내에는
    검색어가 고른 엔진으로 전송될 수 있다고 엔진 이름을 넣어 보여준다
  - 검색 개인화 초기화: 열어본 결과 기록(`search-feedback.json`)만 지우며 검색 데이터 초기화와 따로 동작
- **일반**: 바로가기 키, 언어, 화면 모드(라이트, 다크, 시스템), 로그인 시 열기
  - 로그인 시 열기: macOS 13+의 `SMAppService.mainApp`으로 등록해 시스템 설정 > 일반 > 로그인 항목의
    "로그인 시 열기"에 앱 이름과 아이콘으로 보인다(`login_item.rs`). 기본값은 켜짐이며, 온보딩을 마칠 때 한 번만
    등록한다(`nookive.launchAtLoginInitialized`). 이후에는 다시 등록하지 않으므로 사용자가 끈 설정이 유지된다.
    상태는 저장하지 않고 설정 창이 보일 때마다 macOS에서 읽어, 시스템 설정에서 바꾼 값이 그대로 보인다. 한 번도
    등록하지 않은 앱은 macOS가 `NotFound`로 알려 주므로 꺼짐으로 다룬다. 허용이 필요하거나 등록에 실패하면(번들이
    아닌 개발 빌드 등) 안내와 로그인 항목 열기 버튼을 보여준다. macOS 13 미만에서는 카드를 숨긴다.
- **데이터 관리**: 검색 데이터 초기화, 앱 데이터 삭제
- **정보**: 버전, GitHub·라이선스·이슈 신고 링크

검색 폴더가 바뀌면 `sync_index_manifest(roots)`가 호출된다. 설정 창을 닫아도 검색 HUD는 유지되며,
검색 HUD의 전역 단축키 동작에는 영향을 주지 않는다.
